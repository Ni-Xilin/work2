# 第二工作点资源清单

## 1. 目录边界

第二工作点运行所需资源收敛为四个目录：

| 目录 | 内容 | 是否进入 Git |
| --- | --- | --- |
| `vista_augur/second_workpoint/` | 模型、数据接口、训练器和损失函数 | 是 |
| `vista_augur/configs/` | 实验配置 | 是 |
| `datasets/` | DeepCorr 与 DeepCoFFEA 数据 | 否 |
| `target_model/` | 冻结目标模型代码与本地权重 | 代码进入，权重不进入 |

`Generator_Trainer/` 不再是运行时依赖。第一工作点的任务约束已经由当前代码、配置和技术文档明确保存。

## 2. 数据集

| 数据集 | 路径 | 当前文件数 | 大小 |
| --- | --- | ---: | ---: |
| DeepCorr | `datasets/deepcorr/` | 52 | 4,334,290,449 bytes |
| DeepCoFFEA | `datasets/deepcoffea/` | 5 | 924,596,025 bytes |

DeepCorr 训练集在没有独立 `train_index300.pickle` 时，由完整样本集合排除 `val_index300.pickle` 和 `test_index300.pickle` 后确定；这是当前 `DeepCorrRealDataset` 的既定行为。

## 3. 目标模型

| 目标模型 | 代码 | 权重 |
| --- | --- | --- |
| DeepCorr100 | `target_model/Deepcorr100.py` | `target_model/deepcorr/deepcorr100/tor_199_epoch10_acc0.66.pth` |
| DeepCorr300 | `target_model/Deepcorr300.py` | `target_model/deepcorr/deepcorr300/tor_199_epoch23_acc0.82dict.pth` |
| DeepCorr700 / mDeepCorr | `target_model/Deepcorr700.py` | `target_model/deepcorr/deepcorr700/tor700_199_epoch11_acc0.88.pth` |
| DeepCoFFEA | `target_model/Deepcoffea.py` | `target_model/deepcoffea/.../best_loss.pth` |

配置实际使用的 DeepCorr300 与 DeepCoFFEA 权重均已通过路径存在性检查。顶层目标权重是当前真实训练日志所使用的版本；旧目录中的同名 DeepCorr300/700 文件大小和哈希不同，因此不覆盖顶层版本。

## 4. 运行入口

从仓库根目录运行：

```bash
PYTHONPATH=vista_augur python vista_augur/run_train.py --config vista_augur/configs/second_workpoint_deepcorr300_torch_real_smoke.json
```

服务器运行时需要额外保证配置中的 `backbone_model_path` 指向实际存在的本地 Qwen 模型目录。
