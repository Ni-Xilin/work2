# 真实语义对齐改造与验证报告

## 1. 报告范围

这份报告覆盖两件已经完成并验证过的修改：

1. 把第二工作点默认语义对齐模式改成与 Time-LLM 更一致的 `text_prototypes`
2. 在同一轮中去掉 stub 路径，让两种语义对齐模式都运行在同一条真实训练链路上

## 2. 当前支持的两种语义对齐模式

| 模式 | 当前角色 | 是否保留 |
| --- | --- | --- |
| `text_prototypes` | 默认主方案 | 是 |
| `learned_prototypes` | 对照/消融方案 | 是 |

## 3. `text_prototypes` 到底改了什么

当前实现不再把原型仅仅理解成一组自由参数，而是：

1. 从冻结 Qwen 的 input embedding 矩阵 `E` 出发。
2. 学习一个 prototype probe 权重 `W`。
3. 构造 `E' = W E`。
4. 让 patch token 对 `E'` 做 multi-head cross-attention。

因此，非文本流量 token 现在会先被重表示到“语言模型已经熟悉的 embedding 几何空间”里，而不是只和一组没有语言先验的自由向量做匹配。

## 4. 为什么必须和去 stub 一起做

如果还保留 stub 训练主线，那么即便加了 `text_prototypes`，实验解释也会一直混着一个历史问题：

- 现在观察到的行为，到底来自 paper-faithful 语义对齐
- 还是来自另一条旧训练路径还没完全拔掉

把 stub 删除之后，这个问题就消失了。现在两种模式都共享同一条：

`real dataset -> frozen Qwen -> frozen target -> real loss`

因此后续比较会更干净。

## 6. 这轮改造后的验证口径

当前验证口径不是“模型能 import”，而是三层：

### 6.1 静态验证

- `compileall` 通过
- 配置能按纯 real 路径通过校验

### 6.2 结构验证

- `text_prototypes` 配置会实例化 `TextPrototypeReprogrammingLayer`
- `learned_prototypes` 配置会实例化 `LearnedPrototypeReprogrammingLayer`

### 6.3 运行时验证

- `DeepCorr300 + text_prototypes` 能完成最小真实训练循环
- checkpoint 与 `train_summary.json` 能正常落盘

## 7. 这轮改造带来的实验意义

### 7.1 主方案与对照方案边界更清楚

现在如果你看到：

- `text_prototypes` 更好
- 或者 `learned_prototypes` 更稳

这个结论对应的变量就是“语义对齐机制差异”，而不是“背后跑的是不是不同训练后端”。

### 7.2 后续更大 backbone 的迁移更直接

由于 `text_prototypes` 已经直接依赖真实 backbone embedding，后续从 `3B` 切到更大模型时，实验逻辑是连续的，而不是再做一次“把占位原型升级成真实 embedding 原型”的二次重构。

## 8. 当前结论

这轮改造后的默认建议已经很明确：

- 正式主方案：`text_prototypes`
- 对照消融：`learned_prototypes`
- 两者都运行在同一条无-stub 的真实训练主线上

这样后续不管是做 `3B / 7B` 扩展，还是做 `DeepCorr / DeepCoFFEA` 对比，实验解释都会更稳定。
